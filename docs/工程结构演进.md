# 工程结构演进

本文归纳历史学习工程中观察到的结构演进模式，不表示相关课程工程、厂商组件或完整固件仍由当前默认分支分发。当前可执行证据仅覆盖仓库自建的 [Portable UART RX Core](portable-uart-core.md)。

## 1. 直接控制

最初的 LED 工程在 `main.c` 中配置 GPIO 并直接改变端口电平，重点是 PnM0/PnM1 与端口输出。

## 2. 厂商库

GPIO、UART、Timer、PWM、ADC 等工程逐步使用 STC 外设库。`Config.h` 统一主频，`Switch.h` 管理外设引脚映射。

## 3. 模块封装

按键、数码管、RTC、DHT11 等功能拆分为独立 `.c/.h`：

```text
main.c
  ├─ 初始化模块
  ├─ 调用接口
  └─ 处理应用流程

driver.c / driver.h
  ├─ 配置端口或外设
  ├─ 执行协议时序
  └─ 返回状态或数据
```

## 4. 回调和状态

按键模块使用状态位保存上一次扫描结果，通过函数指针上报按下和释放事件。矩阵键盘把 4×4 状态压缩到 16-bit 位图，再映射为 HID 报告。

## 5. 中断与缓冲

UART ISR 收集字节、主循环消费数据，是历史工程中采用过的职责分离模式。当前默认分支用可移植环形缓冲区明确实现 ISR 单生产者与主循环单消费者边界；未提供 STC8 UART 寄存器集成。Timer0 的 1 ms 中断入口属于历史结构示例，不构成当前板端运行证据。

## 6. 多外设与任务

RTC + OLED 工程同时使用硬件 I²C 和软件 I²C。RTX51 Tiny 工程进一步使用 task、tick 等待和 signal，在 UART 事件与 LED 任务之间传递状态。
