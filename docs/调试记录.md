# 调试记录

## OLED 代码整合

课程记录中出现过三类冲突：

- `delay_ms` 在 OLED 源码和公共 `Delay.c` 中重复定义。
- `REG51.h` 与 `STC8H.h` 重复定义 P0 等寄存器。
- `u8/u16/u32` 在 OLED 头文件和 `Type_def.h` 中重复定义。

处理重点不是删除任意文件，而是明确每个符号只由一个公共头文件或源文件提供。

## Keil Include Path

RTX51 Tiny 和 USB HID 工程采用多目录结构。出现 `can't open file` 时，应先核对 Keil C51 的 Include Paths，而不是复制多个同名头文件到工程根目录。

## UART 与 USB 模式

P3.0/P3.1 同时涉及 CH340N 串口和 USB D-/D+ 路径。串口无输出、HID 无法枚举或下载失败时，先检查板载切换开关和当前工程使用的引脚组。

## RTC 启动时间

部分课程示例在上电后调用 `RTC_WriteTime()` 写入固定时间，便于课堂验证。实际时钟应用应把“首次初始化”和“每次读取”分开，避免每次启动覆盖走时结果。

## 源码检查点

- `KEY_Scan(down, up)` 的参数命名与按下/释放分支疑似相反，检查时应同时核对调用参数和事件分支。
- EEPROM 示例将写入和读取调用注释后仍打印 `str2`，适合作为 IAP 接口和数据路径的阅读样例。
- 板端结果以实际硬件记录为准；历史构建文件仅记录工程曾生成输出。
